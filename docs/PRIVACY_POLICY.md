# ETOS LLM Studio 隐私政策

**生效日期：** 2026年7月26日

## 1. 前言

ETOS LLM Studio 采用 **“本地优先（Local-first）”** 的设计思路。大多数核心数据会保存在您的设备本地，由您自己掌控。

我们**不会在开发者控制的服务器上**默认存储您的聊天内容、语音录音、图片附件或 API Key；但应用本身确实会在设备本地保存聊天记录、配置、记忆、请求日志等数据，以支撑同步、统计、Daily Pulse、年度汇总等功能。

## 2. 设备本地存储与本地处理

### 2.1 本地保存的数据
- **聊天与会话数据：** 聊天记录、会话配置、临时草稿、图片/音频/文件附件引用等会保存在应用沙盒内。
- **知识与个性化数据：** RAG 记忆、世界书、Daily Pulse 数据、反馈历史、任务等会保存在设备本地。
- **本地请求与响应日志：** 应用可在本地保存一次 HTTP 模型请求的完整请求体与响应体，以及提供商、模型、时间、状态、耗时、流式标记和 Token 用量等诊断字段。该功能有独立总开关；默认会隐藏聊天正文，只有您主动开启“记录请求明文消息”后才会保留文本内容。图片、音频和文件的 Base64 内容始终隐藏。此类日志只保存在设备本地，不会自动上传。
- **反馈工单缓存：** 如果您使用反馈助手，应用会在本地保存工单编号、票据令牌、标题、状态、更新时间和公开链接等信息，方便后续查看处理进度。
- **启动保护备份（可选）：** 如果您开启“启动时创建数据库备份点”，应用会在本地额外落盘数据库备份副本，用于数据库损坏时恢复。

### 2.2 凭据存储
- **API 提供商配置：** 提供商配置（例如模型列表、请求头覆盖、代理设置等）保存在本地 **SQLite** 配置数据库。
- **API Key：** API Key 作为提供商配置的一部分保存在本地 **SQLite** 配置数据库。旧版本若曾写入 Keychain，会在升级迁移时合并并清理旧存储。
- 如果您主动启用“提供商配置”相关的同步/导出能力，配置数据（可能包含 API Key）会按您选择的通道在您的设备或目标端点之间传输。

## 3. AI 请求、音频与图片

### 3.1 文本聊天
- 您发送给模型的文本消息会**直接**发送到您自行配置的第三方 AI 提供商（如 OpenAI、Anthropic、Google、兼容 OpenAI 的服务或自建模型）。
- 我们不会在开发者服务器上拦截、转存或训练这些聊天内容。

### 3.2 语音与音频
- 应用仅在您主动点击录音或语音输入时访问麦克风。
- 录音会作为音频附件发送，或交给您配置的语音/转写模型处理。
- 音频不会默认发送给开发者服务器。

### 3.3 图片与文件
- 应用仅在您主动选择图片或文件时访问相关内容。
- 您附加的图片/文件会发送到当前模型提供商或您主动连接的调试端，不会默认上传到开发者服务器。

### 3.4 MCP 服务器与工具调用
- 如果您主动配置并连接 MCP 服务器，请求上下文与工具参数会发送到**您配置的 MCP 端点**处理。
- 工具调用结果与相关元数据会保存在设备本地，用于展示与后续会话流程。
- 对具备审批要求的工具，应用会按您的审批策略执行（例如每次询问、自动同意或拒绝）。

## 4. 同步、本地网络与 Apple 服务

### 4.1 iPhone / Apple Watch 同步
- iPhone 与 Apple Watch 之间的实时同步通过 **WatchConnectivity** 完成。
- 这类同步属于 Apple 提供的设备间通信能力，不经过开发者自建服务器。

### 4.2 iCloud 同步
- 如果您在应用中主动开启 **iCloud 同步**，所选数据会通过 Apple 的 iCloud / CloudKit 体系在您自己的设备之间同步。
- 如果您同步了“提供商配置”，同步包中可能包含 API Key 与其他敏感配置字段。

### 4.3 本地网络与调试
- 应用可能请求本地网络权限，用于可选的 **局域网调试 / 远程文件访问** 功能。
- 如果您主动连接自己的电脑调试工具，相关应用文件或请求流量可能会发送到**您自己控制的本地调试端**，用于查看日志、分析请求或管理应用文件。

### 4.4 导出与手动上传备份
- 应用支持将所选同步项导出为 ETOS 数据包（JSON 封装）并由您手动分享。
- 您也可以手动填写地址，将导出包通过 HTTP POST 上传到该地址。
- 由于导出/上传内容取决于您勾选的同步项，导出包可能包含 API Key 等敏感配置，请仅发送到可信对象或可信端点。

## 5. 反馈助手

### 5.1 何时会向开发者侧服务发送数据
仅当您**主动使用反馈助手并提交反馈**时，应用才会向反馈服务发送数据。

### 5.2 提交反馈时可能发送的数据
- **您主动填写的内容：** 反馈类型、标题、详细描述、复现步骤、预期行为、实际行为、补充说明。
- **环境快照：** 平台（iOS / watchOS）、App 版本号、Build 号、操作系统版本、设备型号标识、语言地区、时区。
- **极简诊断信息：** 时间戳、当前配置的提供商数量、非临时会话数量、平台信息、App 版本信息。
- **防滥用校验数据：** 为了防止垃圾提交，反馈请求还会附带 challenge、时间戳、签名和 PoW 相关字段。

### 5.3 不会自动附带的内容
- 不会自动附带您的完整聊天记录。
- 不会自动附带 API Key。
- 不会自动把本地请求日志整包上传。

### 5.4 脱敏与提醒
- 反馈文本在提交前会做一层**基础脱敏**，尝试遮盖常见的 Bearer Token、API Key 字样和部分常见密钥格式。
- 但这不是完整的数据防泄漏系统。**请不要在反馈内容中主动填写密钥、身份证号、住址、健康信息等敏感内容。**

### 5.5 工单状态刷新
- 如果您之后在反馈中心查看工单状态，应用会使用本地保存的工单编号与票据令牌向反馈服务查询处理进度和评论。

## 6. 性能遥测与诊断

### 6.1 默认状态与控制
- “帮助 ETOS LLM Studio 改进性能”默认开启，可在“设置 > 关于”中随时关闭。
- 关闭后，应用会停止订阅和收集新的性能遥测，并清除设备上尚未发送的遥测文件。
- 性能遥测开关与本地请求/响应日志开关相互独立；关闭请求日志不会关闭性能遥测。

### 6.2 收集与发送的数据
- **Apple MetricKit 数据：** CPU、内存、启动、卡顿、磁盘、网络等系统聚合指标，以及崩溃、卡顿、CPU 异常、磁盘写入异常等系统诊断调用栈（具体类别取决于系统实际提供的报告）。
- **关键阶段耗时：** 使用 Apple `MXSignpost` 记录启动、数据库引导、服务预热、会话消息读取、请求准备、模型请求、流式响应处理和 Markdown 预计算等固定功能阶段的聚合耗时。
- **环境信息：** App 版本号、Build 号、分发渠道（例如 TestFlight / App Store）、iOS 版本、设备型号类别、处理器架构、报告时间范围和捕获时间。
- **完整性字段：** 协议版本、数据类型和根据原始 MetricKit JSON 计算的 SHA-256 内容摘要，用于去重和确认传输，不用于识别用户。

### 6.3 明确不包含的数据
性能遥测不会包含聊天内容、本地请求体、本地响应体、API Key、凭据、您配置的服务器地址、会话 ID、持久设备 ID、广告 ID 或其他用户标识。应用不会为遥测使用 App Attest、DeviceCheck 或 Proof of Work。

### 6.4 发送时机、本地保留与服务器处理
- MetricKit 由 iOS 按系统安排提供聚合报告，并不保证每次启动都有新报告。
- 应用只尝试发送**上一启动已经落盘**的数据；本次启动收到的新报告留到后续启动。发送成功并获得逐条确认后，对应本地文件会立即删除。
- 设备端待发送遥测按日期独立存放，最长保留 14 天且总量上限为 20 MiB；达到上限时优先保留诊断调用栈。
- 接收服务按 UTC 日期临时存放遥测，受 30 天和 2 GiB 总量上限约束。开发者可将这些文件转移到受控的 Mac 进行长期性能分析，并在不再需要时人工删除。
- 接收服务在处理网络请求时不可避免地会临时看到来源 IP，但遥测文件和清单不会保存 IP；IP 仅可用于内存中的短期限流，不作为持久用户标识。

### 6.5 用户可见性与用途
您可以在“应用日志 > 性能遥测”中查看待发送原文，以及本次启动已经成功发送并在内存中暂存的原文。原始诊断地址需配合相同 Xcode Cloud 构建的 `.xcarchive` / dSYM 才能还原为函数、文件和可能的行号。这些数据仅用于定位耗电、发热、卡顿、启动缓慢、内存压力、磁盘或网络资源浪费等性能问题，不用于广告、用户画像或训练聊天模型。

## 7. 第三方服务与开发者服务器边界

当前版本中，可能涉及的数据处理方主要包括：
1. **您自行配置的 AI 提供商**（负责处理聊天、图像、语音等模型请求）
2. **Apple 提供的系统服务**（如 WatchConnectivity、iCloud / CloudKit）
3. **开发者运营的反馈服务**（仅在您主动提交或查询反馈工单时使用）
4. **开发者运营的性能遥测接收服务**（在性能遥测开关开启时自动接收第 6 节列出的非内容型数据）

我们不会把您的聊天内容、本地记忆、本地请求与响应日志、年度汇总数据或 API Key 自动上传到开发者控制的服务器。性能遥测仅限第 6 节列出的非内容型指标、诊断和环境字段。
另外，MCP 调用、iCloud/设备同步、手动备份上传属于您主动配置或触发的路径，其数据流向取决于您选择的目标服务与同步项。

## 8. 分析、广告与崩溃信息

- 当前代码中**未集成第三方广告 SDK**。
- 除第 6 节所述 Apple MetricKit 性能遥测外，当前代码中**未集成通用型开发者侧行为分析 SDK**。
- 如果您在 iOS 系统层面选择与开发者共享分析，Apple 可能会按照其自身规则收集匿名崩溃日志或诊断信息。

1. **中立工具属性：** 应用可能预置部分服务端点或反馈服务地址，但默认不内置可直接使用的商业模型凭据。
2. **内容责任：** 所有 AI 生成内容均由您自行配置的第三方服务提供商返回，我们无法保证其准确性、合法性或适用性。
3. **服务选择：** 您选择使用的任何 API 服务或反馈服务，都应由您自行评估其隐私政策、条款、成本与风险。
