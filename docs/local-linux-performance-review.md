# 本地 Linux 卡顿排查与输出链路优化

## 2026-09-12 单页读取优化与构建复核

iSH 的普通内存读取在 TLB 缓存命中且不跨页时，直接在映射锁及页面同步锁内复核权限和可访问性后复制数据，省去通用分片构造、同步域整理与重复检查。跨页、缺页、文件截断和映射变化继续进入完整预检，失败不写入调用者的目标缓冲区。

相较 `433f9ca4`，同机 Release/threaded 配置下，六组固定循环分别预热两次、交替配对采样十次，每次计时执行 1,048,576 轮并检查最终 CPU、内存及停止状态。五组读取循环的中位耗时下降约 5.5%–13.8%，不涉及读取的算术对照基本持平：

| 固定循环 | 修改前中位耗时 | 修改后中位耗时 |
| --- | --- | --- |
| LDR 立即数寻址 | 57.027 ms | 50.572 ms |
| LDP 成对读取 | 58.849 ms | 50.733 ms |
| SIMD 向量/标量读取 | 186.778 ms | 172.422 ms |
| 算术对照 | 36.879 ms | 36.532 ms |

136 项 Release 回归与 11 项 ASan/UBSan 回归通过，涵盖未对齐和页尾访问、跨页失败、共享别名、文件截断、映射更换及并发读取。以上是内核热缓存微基准，不代表 OpenMinis 同负载比较、App 帧率或手表耗电测量。

App 构建前需要按目标平台和配置运行 `scripts/build-native-static-libraries.sh`，它先调用 iSH 专用构建脚本，再把独立库同步到 Xcode 实际搜索的 `Dependencies/llama-build/products/<平台>-<配置>/`。当前工程不会自动执行这一步；仅更新子模块，或仅运行 `build-ish-static-library.sh`，都可能继续链接旧的暂存副本。手动调用时 `SDK_NAME` 与 `PLATFORM_NAME` 必须同时设置为目标 SDK，并传入对应的 `CONFIGURATION` 与 `ARCHS`。

本轮同时补齐了终端通知接口的 SDK 导出清单，避免最终打包时被局部化而无法链接；后台统计改为创建独立 `FileManager`，消除跨隔离域捕获警告。

最终七切片公共 XCFramework、模块消费者和 Swift 6 SDK 包装检查全部通过（含 arm64_32）。按项目规定执行 iOS Simulator 构建，iOS App、嵌入的 watchOS App 及相关扩展均构建成功。没有执行 ETOSCore 或 App 的 Swift 单元测试；App 构建仍有第三方 `swift-cmark` 的 `DEFINES_MODULE` 缺少 umbrella header 警告，本轮修改的源码没有新增编译警告。

## 2026-09-12 当前实现与验证

guest 仍在独立 pthread 上执行；本轮继续减少输出链路与信号检查的额外工作，没有把模拟器搬到 UI 主线程。

| 路径 | 当前行为 |
| --- | --- |
| PTY 读取 | iSH 通过非阻塞宿主描述符通知输出与退出；App 使用 DispatchSourceRead 等待，空闲时不做 PTY 定时读取。确认退出后再次读空，避免读空与退出查询之间的尾部输出遗漏 |
| 页面刷新 | 收集器发布变化，后台合并输出并生成行快照；iOS/watchOS 分别以至少 100/200ms 间隔合并连续变化，空闲时等待事件 |
| 终端排版 | 历史行冻结，活动行按内容缓存富文本；iOS 使用 LazyVStack、watchOS 使用 List 行，避免把完整历史交给一个巨大 Text |
| 完成与取消 | 最终任务状态保存后才结束页面订阅；取消订阅会停止快照任务，底层读取继续处理会话输出；通知描述符在 DispatchSource 取消回调中关闭 |
| 被屏蔽信号 | 每个线程确认一次共享信号发布世代；解除屏蔽及 sigreturn 重新触发检查，整组退出与 exec 保留强制检查 |

行快照中的空行保留排版高度，但布局占位字符不进入原始日志、纯文本或复制结果。iOS 的整段终端复制菜单在后台拼接纯文本，沿用现有“复制”本地化。按行呈现后，文本选择以单行为单位；跨行内容可通过终端复制菜单获取。未新增配置字段或配置向导操作。

验证结果：138 项相关 C 回归通过；9 项 ASan + UBSan 回归通过。通知管道另补跑并发生产/消费、通知积压、迟订阅、退出、EOF、槽位复用和 fd 不泄漏检查。watchOS arm64_32 完整 C runtime 的三个链接检查及公共模块消费者通过，涵盖新增通知 API。Sanitizer 构建仍有原有 sprintf/vsprintf 弃用警告；本轮 Release 与 watchOS 构建没有新警告。

与上一轮内核 `4d262b45` 比较，相同 Release/threaded 配置、相同 kernel 服务下运行 3,145,731 条 guest 指令，各预热两次、交替配对采样十次：

| --- | --- | --- | --- |
| 无待处理信号 | 83.930 ms | 84.254 ms | 0.997，差异小于本轮波动 |
| 私有 SIGUSR1 被屏蔽 | 291.459 ms | 84.459 ms | 3.456 |
| 共享 SIGUSR1 被屏蔽 | 292.313 ms | 85.044 ms | 3.447 |

这些数据只代表固定内核微基准。尚未做 OpenMinis 相同命令对比、App 帧率或 watchOS 真机耗电测量。诊断队列和浮窗缩略图仍有各自的检查循环；本轮没有实现新的基本块执行器。

Swift App 按用户约束未编译、未运行测试；仅做语法解析、调用点检查与差异检查。已补充通知取消、最终帧、迟订阅、行身份、历史裁剪、备用屏、空行、外观与缩放测试。取得相应授权后应运行 ETOSCore 回归，并在 iOS/watchOS 检查连续输出、滚动跟随、选择与复制、watchOS List 行间距及页面切换。

### App 高频路径的后续优化

- 滚动历史改为有界环形容器，满 2,000 行后覆盖最旧槽位，避免每追加一行搬移整段历史。历史顺序、冻结的行身份、备用屏隔离及清空/缩放行为沿用现有语义；完整显示快照仍需遍历可见历史，这项修改不代表快照生成也变为常数开销。
- 输出文件与屏幕状态使用独立的锁；预览读取不再等待文件写入或模型副本脱敏，仍需与屏幕解析互斥。原始帧的头和正文合并为一次 FileHandle 写入，帧格式不变。模型预算用尽后停止后续匹配和尾部缓存处理，原始日志、终端解析与协议回应继续；未保存的后续秘密不再被记为已脱敏。
- 命令完成只提交工作区统计请求，默认合并 500ms 内的重复请求，目录遍历和大小写回在 utility 后台任务中完成。扫描期间的新增请求会触发后续统计，主动刷新可以共享正在执行的扫描；空闲时没有统计轮询。统计只更新大小，并核对记录 ID、路径和创建时间，避免覆盖新元数据或影响删除后重建的记录。系统关键路径检查仍在任务结束时执行。

这次只修改 iOS/watchOS 共用的 Swift 逻辑，未变更 iSH 内核或工程配置。已新增环形历史、预算边界/跨块脱敏、输出与预览并发、统计合并/失败重试和持久化生命周期回归用例。仅通过 swift-format 语法解析及 git diff 检查，没有编译或执行 Swift 测试；上面的 C 回归和微基准属于此前内核改动，不能验证这次 Swift 修改。后续获准测试时应运行 ETOSCore 回归，并在连续输出、大工作区内重复执行短命令的场景中测量输入响应和完成延迟。

## 2026-09-10 首次排查记录

2026-09-10，通过本地源码检查 App、嵌入的 ish-multiarch、独立 ish-multiarch 工作目录、OpenMinis 及其 ish-arm64。未运行构建、测试或实机性能采样；以下区分已确认的代码行为与尚待测量的影响。

本次未发现“整个 iSH 模拟器直接在 UI 主线程执行”的调用链证据。`iSHAppleBridgeAdapter` 和 `LocalLinuxJobScheduler` 都是独立 actor；PTY 输出由 `.utility` 的 `Task.detached` 读取；guest 执行由内核 `task_start_suspended` 创建的 pthread 承担。这不等于已排除所有卡顿：后台 CPU、内存分配、调度器排队，以及终端长文本在主线程的布局，仍会影响体验。

实际构建来源是仓库中的 `Dependencies/ish-multiarch`，由 `scripts/build-ish-static-library.sh` 消费。本次检查时子模块提交为 `3c4fe752`；`~/Dev/C:C++/ish-multiarch` 为 `6140c26c`，后者仅多出一条文档提交。`tools/apple-core-gate.sh` 为核心配置 release 构建，并为 Apple ARM 切片选择 threaded 后端，没有看到误用纯 C 后端或开启 threaded profiling 的配置。

| 已确认的额外开销 | 本次修改 | 影响范围 |
| --- | --- | --- |
| `LocalLinuxOutputCollector.appendUserPreview` 每个 PTY 分片都调用 `renderedText`，拼接最多 2,000 行历史，即使没有页面读取它 | 继续增量解析协议与及时回包，只将纯文本缓存标记为失效，读取时才生成 | 隐藏终端、持续刷日志、长历史 |
| `LocalLinuxTerminalScreen.put` 和 `mutateBuffer` 先复制 `Buffer` 值，修改嵌套数组后再写回，存在逐字符写时复制开销 | 通过 `inout` 直接修改主屏或备用屏的存储 | 所有终端输出解析 |
| 缩略图先复制完整历史并生成所有屏幕行的富文本，最后才截取末尾几行 | 先选取尾部范围，再为选中的屏幕行生成样式 | 聊天页终端缩略图 |
| 调度器 actor 同步等待收集器锁并生成输出预览，期间输入、中断及其他会话操作可能排队 | 捕获收集器后，在独立后台任务中读取和生成快照 | iOS/watchOS 的任务调度与终端输入 |

空闲 PTY 稳定后，应用层读取检查频率从理论约 200 次/秒降至约 20 次/秒。这是代码中的调度间隔，不是整机 CPU 或耗电降低 90% 的测量结果；新输出最多多等待一个 50 毫秒的轮询间隔，另有系统调度与处理时间。读取、退出结果检查及日志保存继续运行，页面隐藏不会使 guest 因宿主停止读取而堵塞。本次没有新增设置或更改页面字段、文案与向导操作。

两套 AArch64 内核的差异也不能忽略。当前嵌入内核中，`guest/aarch64/runner.c:aarch64_run_one` 每次取一条指令；`guest/aarch64/threaded.c` 使用缓存解码与 C handler；`guest/aarch64/linux-process.c:aarch64_linux_process_run_one` 在普通指令完成后调用 `aarch64_linux_poll_signals`，再返回 task 循环。相对地，本地 `~/Dev/C:C++/ish-arm64/asbestos/guest-arm64/gen.c` 构造基本块的 gadget 序列，由预编译汇编 gadget 执行。因此，两者虽然都称为 threaded 后端，单条指令的处理路径已不相同，CPU 密集任务可能有明显差异，不能用同源或没有死循环推导出接近的性能。本次没有修改指令执行、信号时序或子模块版本。

OpenMinis 的宿主接入也有不同：`src/ios/iSH/ISHShellExecutor.m` 用后台 reader queue 与 `poll` 等待命令输出；`TerminalCanvasView.swift` 缓存已冻结的历史富文本，避免无关 SwiftUI 更新触发重建。它在 App 进入后台时开启 80% duty cycle 的 guest 节流，前台关闭，因此这段节流不能直接解释前台界面是否流畅。以上来自源码检查，没有采用其 README 中的跑分作为本项目的性能证据。

已补充 `LocalLinuxTerminalOutputPipelineTests` 和 `LocalLinuxTerminalScreenTests` 用例，覆盖无预览订阅时的原始帧完整性与协议回包、三种预览缓存的独立刷新、缩放、主备用屏隔离、历史与屏幕边界、空白行及背景样式、已发布快照不被后续修改，以及空闲退让和满块读取。本次仅做静态调用点检查与 `git diff --check`，按项目约定未执行这些测试。

实际流畅度仍需使用用户触发问题的命令，在相同设备、相同前后台状态下采样确认。验证应同时记录主线程耗时、guest 线程 CPU、输出速率与输入响应，并区分“计算但不输出”“持续输出”“隐藏终端”三种情况。纯计算的执行器速度不会因本次终端优化自动接近 ish-arm64；完整终端目前仍用一个 SwiftUI `Text` 呈现长历史，其主线程布局成本也是尚待实机采样确认的剩余因素。
