## 补充复查：普通 HTML 代码框的预览入口

用户进一步明确：工具 widget 与正则拆分出的 HTML 气泡可以渲染，普通消息中的 HTML 代码框预览失败。按这个入口重新检查后，**确认了业务缺陷**。下文“上一轮”中的未复现结论仅适用于当时覆盖的路径，不能用于判断普通代码框没有问题。

### 历史与原因

`02e47a68` 为 iOS 的 `html/htm/xhtml/xml/svg` 代码框加入 Safari 图标，点击后通过 WKWebView 预览；当前入口仍存在。上一轮运行用例创建了角色卡绑定，HTML 被提取成 `RoleplayHTMLCardView`，绕开了普通 Markdown 代码框及其预览按钮，漏掉了本次故障路径。

普通代码框在高级渲染开启时会经过 `ETMathContentParser` 和原生公式 Markdown 转换。旧解析器没有排除代码范围，会把 JavaScript 的 `$` 变量或 TeX 字面量当成公式。例如：

```javascript
const $ = id => document.getElementById(id);
$('code-preview-probe').textContent = '脚本运行成功';
```

预处理后变成 `const ![数学公式](etmath://...)('code-preview-probe')...`，破坏脚本语法，随后预览页无法执行。正文与代码中的单个美元符还可能跨围栏配对，把代码围栏一并替换，影响代码框和预览入口。工具网页与角色卡拆分 HTML 不走这段转换，因此不受同一错误影响。

此缺陷的解析逻辑在 `90abb52b` 前已经存在；相关解析器、预处理和预览文件在远端基线 `1e4c7d46` 与本轮起点 `2f159da1` 之间没有变化。

### 修复与验证

共享解析器复用已有 Swift Markdown 语法树确定围栏、缩进代码与行内代码的源范围，只在代码范围外识别公式。代码内容原样保留，代码外的公式继续渲染；中文与 emoji 按 UTF-8 源位置换算。修复适用于 iOS/watchOS，沿用现有后台准备与缓存。

验证文件位于 `/tmp/etos-code-preview-review-20260914/`：

- `before-runtime`：有效的修复前运行证据。真实无角色卡普通会话、真实代码框无障碍按钮激活和 WKWebView；关闭高级渲染的场景通过，开启时脚本执行断言失败，两个场景一过一败。截图已目视确认代码中出现被替换的 `etmath` 标记。
- `core-after`：公式解析与流式 Markdown 相关三个套件，39 个测试函数、47 个场景通过，无失败、无跳过。

- `app-after`：普通、高级渲染、公式混排、完整文档、流式结束后的五种真实预览均通过；原有角色卡/正则 HTML、工具网页、流式/版本切换及公式图片并发回归也通过，共 **6/6 个测试函数、15/15 个场景**，无失败、无跳过。iOS 与嵌入 watchOS App 构建通过，只有原有 swift-cmark 两条 umbrella header 警告。
