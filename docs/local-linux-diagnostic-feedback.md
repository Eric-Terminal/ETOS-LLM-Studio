# 本地 Linux 诊断共享

命令和终端的 iSH 原生诊断事件经现有 `LocalLinuxDiagnosticsRecorder` 采集后，iOS/watchOS 会询问是否共享给开发者。无需配置模型，也无需把终端文字手动粘贴到聊天里；允许后使用固定、本地化的问题说明直接调用 `FeedbackService.submit`，工单出现在现有反馈助手中。

## 行为与数据边界

- 每个任务只征询一次，重复事件合并到待确认报告。终端无需退出，命令结束也不会清掉尚未确认的事件。
- 尚未允许或选择“暂不发送”时不调用反馈服务。允许后固定当时已采集的事件；后续事件不会追加发送。发送不依赖页面继续显示，不取消 Linux 任务。
- 网络失败显示重试入口，重试沿用已同意的报告。未发送或失败的待确认状态仅在本次 App 进程内保留；原有设备本地诊断日志不受影响。
- 发送内容包含完整事件字段、进程名、内核构建标识、执行后端、指令地址、opcode、系统调用、信号、errno、任务标识、采集时间，以及系统种子版本。64 位地址和编号额外保存字符串，避免后续 JSON 消费方损失精度。
- 沿用反馈服务的应用/设备环境信息、基本运行统计与脱敏规则。不读取聊天内容、命令参数、环境变量、工作目录或终端输出。固定说明明确不推测缺失的复现步骤。
- 终端、Linux 页面和根聊天页共用一个弹窗协调器。顶层正在显示其他错误、终端分页不可见或 App 处于后台时延后提示。

此入口处理已经由命令/终端诊断队列采集到的原生事件（包括不支持的指令与系统调用）。普通命令非零退出、没有原生事件的 Swift 操作错误，以及未接入该队列的 runtime/guest-file scope 不会凭错误文案自动生成报告。既有终端诊断摘要、模型诊断结果和手动反馈入口继续有效。

已核对本机 `ish-multiarch/sdk/iSHApple/Headers/iSHAppleDiagnostics.h`，所需字段均已存在，因此无需修改或重新打包 iSH。共享流程复用已排出的事件，不增加轮询或第二个原生队列消费者。

## 验证

新增 `LocalLinuxDiagnosticFeedbackTests`，覆盖空事件、跨批次合并、任务结束后共享、明确同意前不发送、拒绝后不重复征询、失败重试保持原报告、重复点击不重复提交、完整数值及隐私字段边界，以及顶层弹窗归属。原有终端诊断测试使用独立反馈缓冲区，避免污染全局弹窗状态。

依照项目约定，本次不运行构建或测试。授权后应运行 ETOSCore 测试，并在 iOS/watchOS 上分别验证手动终端、Agent 命令、聊天内嵌终端及 sheet 中的终端：触发原生兼容性事件，检查拒绝无网络请求；允许创建工单；断网重试不增加事件；任务提前退出仍保留报告；切换页面或后台后不会重复弹窗。实际反馈提交应使用开发服务，避免产生测试工单。

这是原生系统确认弹窗与发送回执，没有可配置字段或独立设置页，不向页面向导暴露代替用户同意、直接提交诊断的操作。
